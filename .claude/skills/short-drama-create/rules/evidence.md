# 证据留存(创作复盘回放)

> 对应设计文档 §8"证据 log"。目的:**创作复盘回放**——记下每一步(当时想法/为何改/哪个版本被淘汰/失败原因),下次创作更高效。

## 存储位置

每部剧:`short-dramas/{slug}/evidence/`

```
evidence/
├── log.md        # 可读的时间轴(人类复盘用)
├── log.jsonl     # 机器可处理的结构化追加(脚本分析用)
└── requests/     # 镜头生成请求快照(每镜 1 个 JSON)
    └── shot_01_v0.json
```

## log.jsonl 条目格式

每行一条 JSON,追加写入(不覆盖):

```json
{
  "ts": "2026-08-03T14:30:00+08:00",
  "type": "资产|剧本|分镜|镜头|任务|验收|成本|补丁|复盘",
  "slug": "my-drama",
  "episode": "ep01",
  "artifact": "assets/characters/lin_nianan/voice_neutral.mp3",
  "params": { "关键参数" },
  "reason": "决策理由(为什么这么做)",
  "version": "v0",
  "cost": { "usage": { "total_seconds": 5 } },
  "result": "PASS|FAIL",
  "failReason": "提示词|参考图|敏感|规格|音频音色"
}
```

## log.md 格式(人类可读)

```markdown
# 创作证据 log — {slug}

## 2026-08-03
- [剧本] ep01 初稿生成,钩子采用"照片反转"
- [剧本] ep01 迭代 2:男主台词改口语化(原太书面)
- [资产] 林念安 声音锚(中性/怒)生成,LOCKED
- [镜头] shot_01_v0 生成,FAIL:脸与黄金锚不一致(参考图问题)
- [镜头] shot_01_v1 生成,PASS
- [成本] ep01 已用 ¥X,重做率 3/10
```

## 追加规则

1. **每次产出都记**:剧本/分镜/资产/镜头/验收/成本/补丁,每次产出或决策追加一条
2. **决策必带 reason**:记"为什么这么改",不记"结果是什么"(结果在文件里)
3. **失败必带 failReason**:按原因分类(提示词/参考图/敏感/规格/音频音色),供集级复盘统计
4. **成本必带 usage**:从任务响应的 `usage` 字段记(总秒数/输入秒数/输出秒数/图数)
5. **请求快照必存**:每镜生成的完整请求体存 `evidence/requests/shot_XX_v{NN}.json`(供 regeneration/补丁复用)
6. 追加不改历史——已写的条目不修改(保持时间轴真实)

## 集级复盘输出(每集收尾,Step 13)

```markdown
## ep01 复盘
- 成本:草稿 ¥X(768P,N 次) + 2K ¥Y(regeneration,M 次) = 合计 ¥Z
- 重做率:FAIL 3 次 / 生成 10 次 = 30%
- 失败分布:提示词 1 / 参考图 1 / 音频音色 1
- 教训:特写镜头容易脸漂,需多带参考图;雨景音效 H3 表现差,B 轨兜底
```

## 复盘回放用法

- 新一集开始:读上一集复盘(失败分布 → 前置校验重点;教训 → 提示词模板)
- 新一部剧开始:读前剧复盘(复用经验,供 v2 学习闭环)
- 补丁模式:读请求快照(复用原始参数重生成)

## 生命周期

- 证据不删(除非用户明确要求)——它是复盘回放与 v2 学习闭环的原材料
- 日志文件小(JSONL 追加),无需轮转
